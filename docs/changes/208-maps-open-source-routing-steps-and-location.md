# 208: Maps: open-source routing with steps, honest modes, named location problems (2026-11-25)

Owner asked for Maps / Places / Directions (scorecard 72.7 %, 3.5 stars) to be lifted by real engineering, with open-source services where that helps. Research and policies: `docs/research/directions-and-reminders/02-open-source-routing-and-location-research.md`. Earlier record: `docs/changes/193-...`.

## What was wrong

1. Without a Google key the answer was a guess: the OSRM demo server was asked for the car route only, bike time was 0.85 x car, walking was 12 minutes a km, steps were not available ("they need a Maps key"). **Probed 2026-11-25: the OSRM demo answers every profile with the car profile**, so any walking or cycling time taken from it would be a car time.
2. The place lookup had one hard-coded address, no cache, no pause after a refusal and no way to move it, against Nominatim's policy (cache results, 1 request a second, switchable without a release). One spoken question started up to three concurrent lookups of the same place.
3. A trip reminder to "home" re-measured the time every 10 minutes by sending the resolved home address to Nominatim (found while tracing the callers of `place_card::quick_route`).
4. Any location failure said the same fixed sentence. Windows refusing the app, the switch being off and "no sensor" are different things to fix.

## What was built

* `src-tauri/src/open_routing.rs` (new): `geocode` (Nominatim, cached 24 h / not found 10 min, one lookup at a time, 1.1 s gap, pause after 429/503/403 honouring `Retry-After`, answer size cap, an application-name User-Agent, percent-encoded query), `route` (OSRM: FOSSGIS `routed-car` / `routed-bike` / `routed-foot`, the demo for driving only, your own OSRM server with the standard profile names), `plan` (resolve places, route through stops; refuses any home/work/"my X" name before a single request; public transport is `Unsupported`; avoid options the open map cannot do are listed in `OpenRoute.ignored`), step text from OSRM maneuvers ("Turn left onto NH765, then 240 metres to the next turn", "At the roundabout take the second exit onto Ring Road", "Reach stop 1", "Arrive at your destination, on your left"), typed errors that carry no place name or coordinate, and a spoken sentence for each.
* `directions.rs`: the order is Routes API (key) -> open map -> the old estimate. The open route gives real distance and time **for the chosen mode** and fills the steps for "read the steps" / "next step" (the full list goes to the sidebar with the OpenStreetMap / FOSSGIS attribution). A car answer says "about 8 minutes by car via Charminar Road, without live traffic"; an estimate still says "roughly". Honest notes after the answer: avoid tolls/highways/ferries ignored (public servers cannot do them), public transport needs a key, why the open map failed (offline, busy, unknown place, no route for that mode), "measured from your approximate position". New `Current.open_ok`/`steps_open`, `Trip.private` (serde default false, old reminders load), `open_path_allowed`, `no_steps_line`. "How long now" and "read the steps" work without a key. A trip to your own place is only timed with a Maps key and is never re-measured through the open services. A private stop added later switches the open route off for that trip.
* `place_card.rs`: the place lookup and the card's car time go through `open_routing` (shared cache and limiter); the old `parse_osrm` and the demo URL are gone.
* `location.rs`: `Problem` (`Denied`, `Off`, `NoSensor`, `NoFix`) from the failed request's error code (E_ACCESSDENIED) and `Geolocator.LocationStatus`, with a sentence for each.
* `commands.rs`: settings `openGeocoderUrl` and `openRoutingUrl` (empty = public defaults; only `https://` or a private network address is accepted). No new on/off switch, so the Features-page gate is unaffected; routing mode in Command Hub (auto/server/google/open) is unchanged.

## Tests

`cargo test --lib -- open_routing:: directions:: location:: commands::tests::open_service place_card::` -> **71 passed, 0 failed** (open_routing 28 new, directions 23 of which 6 new, location 4 of which 1 new, settings round trip 1 new, place_card 15). `cargo check --lib` clean with no warnings. `check-feature-registry`, `check-ipc-contract`, `check-turn-ends`, `check-hardcoded-colors`, `check-repo-hygiene` pass. Not run: the dead-code ratchet, the full lib suite, the frontend suite (no frontend change).

* The mock-server tests start a local HTTP server (the repo's `memcore::test_http`) and cover: success, empty result, HTTP 429 with `Retry-After` and the pause that follows, a pause cap, HTTP 500 and 502, malformed JSON, a proxy login page instead of JSON, an answer over the size cap (with a `Content-Length` and chunked with none), a slow service (timeout mapped), an absent service (offline), OSRM's HTTP 400 "NoRoute", the one-request-a-second gap, the cache (a repeated place and a not-found place send one request), percent-encoding of `#`, `%`, `&`, `é` and `東京`, steps parsing (depart, turn with only a road ref, roundabout exit, stop vs destination), profile choice per mode and per server (FOSSGIS car/bike/foot, the demo is car only, your own server), avoid options reported as ignored (driving only), public transport refused, and **that a home/work/"my X" name, as destination, start or stop, never produces a request to the geocoder** (the mock records every request).
* Mutation check (`docs/testing/runs/maps-mutations-20261125.json`): 17 rules removed one at a time, **17 of 17 caught by an assertion**: private-place gate, the up-front refusal, the car-only demo rule, the geocode cache, the pause after a refusal, the stream size cap, percent-encoding, the request gap, `Retry-After`, the ignored-avoid report, the zero-distance route refusal, "without live traffic", a private stop switching the open route off, `open_path_allowed`, the attribution, the Windows location refusal, and the old-reminder serde default. The first run found one real gap (the size cap: the mock always sent a length, so the streaming check was never exercised); the chunked test was added and the rule re-run. Six directions/location mutants were invalid in the first run (compile errors while another session was editing other files) and were re-run on a clean tree.

## Not verified

* Everything against the real public services at length: only one probe request per service was made (see the research note). Behaviour under their rate limits, outages and slow answers is tested against a local mock server, not against them.
* The spoken sentences on the real speaker; the Windows location refusal wording on a machine where location is actually refused; a trip reminder firing on an open-map time; the Maps window and the place card together under the 1 request a second gap (the card builds in parallel and may take about a second longer).
* Transit (needs a Maps key), live traffic (needs a Maps key), avoiding tolls on the open path (the public servers do not support it).
