## One-paragraph summary

REA is a 320k-star MIT CLI/MCP kit whose browser lane is **passive by construction** — it attaches to a Chrome you start yourself (`--remote-debugging-port` on loopback, disposable profile — REA never launches/owns/terminates it) and its documented non-goals (no `Runtime.evaluate`, **no navigation, input, downloads, closures**) match the owner's observe-only law almost verbatim. The one exception family (Playwright scenarios) is simply never exposed: teardown whitelists only the passive CDP commands and negative-tests the rest. The npm package is the genuine article (repository.url = `git+https://github.com/morluto/rea.git`, MIT, SLSA provenance, published by GitHub Actions); the pin is **`rea-agents@6.7.0`** installed `--save-exact --ignore-scripts` into `~/.nexus-tools/rea` (which also blocks frida's native postinstall — the right outcome). Invocation is always `node $HOME/.nexus-tools/rea/node_modules/rea-agents/scripts/rea.mjs <command> --json` so no PATH is needed; the stdlib-only teardown bay soft-imports as an `APIRouter`-free module into the existing FastAPI sidecar and answers `/teardown/diag` with ready/node/chrome/versions + one plain-English line per missing piece — degrading to an explicit degraded route so nothing ever crashes.

**Verified live on the build machine (2026-10-19, later pass):** Node **v24.12.0** on PATH ✓; Chrome found at `C:\Program Files\Google\Chrome\Application\chrome.exe` ✓; `rea-agents@6.7.0` installed under `~/.nexus-tools/rea` with `--save-exact --ignore-scripts` after checking its npm repository URL and integrity. The installed package reports version 6.7.0 and the official repository, and `capabilities --json` plus passive-command `--help` run successfully. The documented global JSON flag is `--format json`.
