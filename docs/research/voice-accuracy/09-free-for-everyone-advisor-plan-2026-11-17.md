# Plan: understanding what the user meant, free for every user on any laptop (2026-11-17)

Status: **plan only.** Supersedes the runtime part (Track 1) of note 08. Nothing in the app, settings or code changes with this note.

## What changed, and why note 08 no longer fits

NEXUS is an **open-source assistant for every user, on any laptop, running on free keys** (Groq and Gemini free tiers, bring-your-own-key, a 600 to 700 MB memory ceiling, no GPU). Note 08 put Claude Opus 5.5 in the live path of every user's commands. That cannot be the design: it is a paid model, each user would need a paid key, and an open project must not depend on one.

Two facts about free tiers also shape the plan:
- **Free-tier numbers are not stable or well published.** One source says Google no longer lists per-model free limits and shows them only per project in the AI Studio console, and secondary sources disagree widely on the daily Flash numbers and on which Flash-Lite models still exist ([search summary of Gemini free-tier pages](https://ai.google.dev/gemini-api/docs/rate-limits)). Groq's own rate-limit page shows the Developer-plan table and sends free-plan users to their account's limits page ([Groq rate limits](https://console.groq.com/docs/rate-limits)); for `whisper-large-v3-turbo` it lists 20 requests a minute and 2,000 a day, with 28,800 audio seconds a day on that table. So the design must **read limits at run time and degrade**, never hard-code them.
- **Every user's room, microphone and accent differ**, so a fix tuned on one laptop (note 05) must be measured across many.

## The principle: put intelligence where it costs nothing to the user

| Where | Who pays | What lives there |
|---|---|---|
| **A. On the laptop, no key** | nobody | Everything needed to be correct on the common cases: command grammar, homophone and vocabulary data, the phoneme-matching layer from note 06, the user's own learned corrections, numbered "which one?" questions. Tiny CPU cost. |
| **B. The user's own free keys** | the user's free quota | Groq speech prompt biasing and word confidence, and a **free language model as the runtime advisor** for the few turns A cannot settle (Gemini Flash-class, Groq or Cerebras chat models through the existing router). |
| **C. The maintainers' premium advisor** | the project, a few calls a week | **Claude Opus 5.5 working offline** on community miss reports to improve the shared data that every user receives. |

This keeps the open-source promise: a user with **no keys** still gets layer A; a user with free keys gets A plus B; every user benefits from C without ever holding a Claude key. Anyone who wants a stronger model can add it later as an optional provider through the same interface (off by default), but nothing requires it.

## Layer A: works with no key on a low-end laptop

1. **Command grammar and the intent tiers** (note 07): exact templates first, then the existing small on-device intent model with a **confidence-gated execute-or-ask** rule and the score logged.
2. **Phonetic slot matcher** (note 06 prototype): closed lists for each slot, phoneme distance, margin rule, usage prior. Needs only a pronunciation dictionary plus the grapheme-to-phoneme tool already shipped. Memory cost is a few megabytes at most.
3. **Homophone and vocabulary data generated by us** from an open pronunciation dictionary plus the user's own app, contact and repo names. Microsoft's files are not copied.
4. **Numbered recovery questions** ("Antigravity or Copilot? Say one or two") and a user-owned vocabulary list.
5. **Learning from the user's own fixes**, using the existing two-sighting rule and the Memory-page list with delete.
6. **Local Moonshine as the recogniser when offline.** No new always-on model is added.

## Layer B: the free cloud advisor (optional, with the user's own free keys)

- **Role is unchanged from note 08:** it has no hands. It receives a minimal redacted payload (transcript, low-confidence words, the closed candidate list with ids, foreground app category), and returns strict JSON (`pick` from the given ids, `ask`, or `unknown`). Code validates it; safety actions keep their own confirmations.
- **Provider order follows the keys the user has,** through the existing 9Router cascade (Cerebras, Groq, Gemini). With no keys, or in local-only mode, this layer simply does not exist and A handles everything.
- **Free-tier discipline (the new part):**
  - The advisor is **last in priority**: speech recognition first, command parsing second, the advisor third. It never uses the last of a user's quota.
  - **Never assume a limit.** Read the response headers and 429 / retry-after, keep a per-provider circuit breaker with back-off, and fall back to A the moment a provider says no.
  - A **daily self-budget** the user can see and change, defaulting low, and a visible "advisor calls today" counter on the Features page.
  - Cache repeated questions; skip the call when the local margin is already confident.
  - **Latency rule unchanged:** ask the user the local numbered question in parallel and take the advisor's answer only if it arrives within about 1.2 s with high confidence.
- **Shadow mode first.** The advisor runs, its answer is logged and never used, until a week of data shows it agrees with the user's final choice at the agreed rate. Same pattern already used for unattended shutdown.

## Layer C: Opus 5.5 as the maintainers' offline advisor (the reviewer from PR 68, reframed)

`scripts/weekly_reviewer.py` becomes a **maintainer tool**, not a user feature.

1. **Miss reports come from the community, opt-in.** Two channels, simplest first:
   - **Manual export:** a Memory-page button writes a small redacted file of the user's recent mis-heard command lines; the user reads it and, if they choose, attaches it to a GitHub issue or pull request. No server, no account.
   - **Later, optional upload** to the project's existing Worker with explicit consent, shown payload, and an off switch.
2. **Redaction before anything leaves the laptop:** the same filters as the reviewer (command-shaped only, no contact details, nothing sensitive), the user's own names removed, and the user sees the exact file.
3. **Maintainer runs the reviewer weekly** on the pooled reports. Opus 5.5 returns proposals only, and the script validates them.
4. **A human reviews every proposal and merges it as a normal pull request** into shared data files (homophone groups, vocabulary, phrasings, confusing pairs). Requiring the same slip in reports from two or more users, or a maintainer's own confirmation, keeps one person's oddity from becoming everyone's rule and limits poisoning.
5. **Delivery to every user** rides the channel that already ships model updates (hash-verified downloads, the way the language-model update works), or ordinary app updates. Data files are signed or hash-pinned.
6. **Licence and consent:** contributed lines are released under the project's licence by the contributor's choice; no audio is ever collected; shared data is generated from open sources, not copied from commercial products.

Cost to the project: a handful of Opus calls per week. Cost to users: zero.

## Making it work for many people and machines

- **Accents and microphones:** build the confusion set from several people and laptops, using the cohort pilot plan (note 04), and report results per group, not as one average. The Intel microphone gating found in note 05 will not be the only odd driver.
- **Language:** English-only for now (the earlier owner decision); other languages get one honest "not supported" line.
- **Hardware floor:** CPU-only, no required GPU, nothing added to the always-on memory budget; every new component must state its megabytes and be switchable off on the Features page.
- **Privacy default:** local-first. Audio goes only to the speech provider the user chose; the advisor sees text only; contribution is opt-in.

## Phases

| Phase | What | Exit gate |
|---|---|---|
| P0 (done) | Maintainer reviewer tool (PR 68): dry-run, redaction, validation, owner approval | Tests pass; one live run by a maintainer produces reviewable proposals |
| P1 | Layer A in the app: entity-built prompt, word confidence, phonetic slot matcher, numbered asks, confidence-gated execute-or-ask, score logging | Offline confusion-set replay: wrong corrections near zero; works with no key; memory and CPU numbers reported |
| P2 | Layer B in **shadow mode** with the user's free keys | A week of logs: agreement rate, 429 rate, calls per day within the self-budget |
| P3 | Manual miss-report export from the Memory page | A maintainer can run the reviewer on exported files from at least three users |
| P4 | Shared data channel: reviewed proposals ship to all users | A data update reaches a test machine, hash-verified, and measurably fixes a real slip |
| P5 | Layer B live (ask-assist) behind a switch | Owner and cohort trial: no added delay, no wrong actions |
| P6 | Optional: consented upload; optional bring-your-own stronger provider slot | Only after P4 is stable |

## How we will know it works for "every user"

Report each of these with numerator and denominator, and per cohort (laptop, microphone, accent):
- **No-key case:** corrected, wrongly corrected, asked, left alone on the confusion set.
- **Free-key case:** the same, plus added latency (p95), advisor calls per user per day, 429 rate, fall-back rate.
- **Footprint:** added memory and CPU on the weakest test laptop.
- **Community loop:** proposals received, accepted, and the measured fix rate of shipped entries.
Ship a layer only if it does not raise the wrong-action rate.

## Risks

| Risk | Answer |
|---|---|
| Free-tier limits shrink or a model is withdrawn (reported for Flash-Lite) | No hard-coded limits or model names beyond a default list; live limit reading; A works alone |
| Users without any key | Layer A is the whole product for them; B and C only add |
| Ambient speech in shared files | Command-shaped lines only, redaction, user reviews the file, opt-in |
| Data poisoning through contributions | Two-user threshold or maintainer confirmation, human review, signed delivery |
| Over-correction | Closed lists, margin rule, ask when close, learned rules deletable |
| Legal | No copied vendor data; open pronunciation sources; contributor consent and licence stated |
| Added latency | Parallel ask; the advisor can only speed a turn up |
